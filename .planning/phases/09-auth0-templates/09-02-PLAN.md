  <name>Task 1: Create Auth0 JWT verification middleware</name>
  <files>packages/create-aws-starter-kit/templates/apps/api/src/middleware/auth0-auth.ts</files>
  <action>
Create auth0-auth.ts middleware that verifies Auth0 JWT tokens, matching the interface of cognito-auth.ts.

Implementation:
1. Use jose library directly for JWT verification (express-oauth2-jwt-bearer is Express-specific, but our Lambda handlers don't use Express)
2. Create AuthUser interface matching cognito-auth.ts structure:
   - sub: string (from JWT sub claim)
   - email?: string (from JWT email claim if present)
   - permissions?: string[] (from JWT permissions claim - Auth0 uses permissions not groups)
   - tokenPayload: JWTPayload (full payload for additional claims)

3. Create verifier outside handler for JWKS caching:
   - Use jose's createRemoteJWKSet with Auth0's JWKS endpoint: `https://${domain}/.well-known/jwks.json`
   - Use jose's jwtVerify for token validation
   - Verify audience and issuer claims

4. verifyToken(authHeader: string | undefined): Promise<AuthUser | null>
   - Extract Bearer token from Authorization header
   - Verify with jose's jwtVerify against JWKS
   - Return AuthUser on success, null on failure
   - Log verification failures

5. requireAuth wrapper - same pattern as cognito-auth.ts:
   - Extract auth header from event
   - Call verifyToken
   - Return 401 if no user
   - Pass user to wrapped handler

Environment variables:
- AUTH0_DOMAIN (e.g., tenant.auth0.com)
- AUTH0_AUDIENCE (API identifier)

Use {{PACKAGE_SCOPE}} token for common-types imports.
  </action>
  <verify>tsc --noEmit in create-aws-starter-kit package passes</verify>
  <done>auth0-auth.ts exports AuthUser, verifyToken, requireAuth matching cognito-auth.ts interface</done>
</task>
